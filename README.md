# «мягко» — шаблон веб-приложения выездной химчистки мебели

Next.js 16 + React 19 + Three.js. Клиент выбирает мебель, видит 3D-персонажа и предварительный расчёт, собирает корзину и отправляет заявку с фото. Владелец принимает заявки и настраивает тарифы в кабинете `/admin`.

Все контакты и сведения компании в шаблоне демонстрационные. Реальных заявок, баз данных и ключей в пакете нет.

## Быстрый запуск (локально)

1. Установите **Node.js 24 LTS** (минимум 22.13 — нужен встроенный модуль `node:sqlite`): https://nodejs.org
2. Распакуйте архив и откройте терминал в папке `MYAGKO_CLEANING_TEMPLATE`.
3. Установите зависимости строго по lock-файлу:

   ```bash
   npm ci
   ```

4. Создайте `.env.local` из шаблона:

   ```bash
   cp .env.example .env.local
   ```

   В Windows PowerShell: `Copy-Item .env.example .env.local`

5. Задайте свои секреты в `.env.local`: `SESSION_SECRET` и `OWNER_PASSWORD` (подробно — [docs/ENVIRONMENT.md](docs/ENVIRONMENT.md)). `DATABASE_URL` для локального запуска можно оставить пустым.
6. Запустите:

   ```bash
   npm run dev
   ```

7. Откройте http://127.0.0.1:3000. Кабинет владельца — http://127.0.0.1:3000/admin.

В локальном режиме без `DATABASE_URL` приложение само создаёт папку `data/` с SQLite-базой. Если `SESSION_SECRET` и `OWNER_PASSWORD` не заданы, ключи генерируются в `data/local-access.json`, а в кабинете появляется кнопка «Войти в локальное демо» (только на 127.0.0.1/localhost). Папка `data/` в `.gitignore` — не публикуйте её.

Демо-данные не нужны: при пустой базе используются настройки компании по умолчанию из `src/lib/domain.ts`.

## Проверки

```bash
npm run check      # TypeScript, без сборки
npm test           # unit-тесты расчёта и валидации
npm run build      # production-сборка
```

Интеграционный тест API (нужен запущенный локальный сервер, работает только с вымышленными данными и удаляет свои записи):

```bash
node tests/integration.mjs
```

Не запускайте его против production с реальными клиентами.

## Продакшен

1. Подключите собственную базу Postgres (Neon, Supabase или свой сервер). Таблицы создаются автоматически при первом запросе; схема с ограничениями — в `postgres-schema.sql`, её можно применить вручную: `psql "$DATABASE_URL" -f postgres-schema.sql`.
2. В настройках хостинга пропишите переменные окружения: `DATABASE_URL`, `SESSION_SECRET`, `OWNER_PASSWORD`, `NEXT_PUBLIC_SITE_URL`.
3. Сборка и запуск: `npm ci && npm run build && npm run start`.

На Vercel: Framework — Next.js, Root Directory — корень этого пакета. Без трёх серверных переменных приложение на Vercel намеренно не стартует, чтобы не работать на временной SQLite. Настройки Vercel-проекта в пакет не входят — создайте свой проект.

`npm run start` слушает `127.0.0.1`. Для собственного сервера за reverse-proxy это нормально; если нужно слушать все интерфейсы, запустите `npx next start --hostname 0.0.0.0`.

## Безопасность зависимостей

Это вариант шаблона с обновлёнными зависимостями: `next@16.4.5` (было 16.4.0) и `sharp@^0.35.5` (было ^0.34.5). Эти версии закрывают известные на ноябрь 2026 уязвимости: critical в Next.js (RCE через Image Optimization API с SVG и через `use cache`, DoS в Server Actions) и high в sharp (libvips, libheif, librsvg). Код приложения не менялся.

`npm audit --omit=dev` — 0 уязвимостей. Полный `npm audit` показывает 4 moderate в `glob`/`minimatch`: их тянет только dev-инструмент `@gltf-transform/cli` (пересборка 3D-моделей), в рантайм и в сборку сайта он не попадает. Предложенный npm «фикс» откатывает CLI на 3.x, поэтому он не применён.

Перед публикацией периодически проверяйте `npm audit` и обновляйте зависимости.

## Адаптация под свою компанию

Название, телефон, email, город, зона выезда, цвет, тарифы, персонаж и режим мини-игры меняются в кабинете `/admin` и сохраняются в базе. Значения по умолчанию — `defaultConfig` в `src/lib/domain.ts`. Пока телефон и email демонстрационные (`+7 000…`, `*.example`), сайт их не показывает.

## Частые проблемы

| Симптом | Причина | Что сделать |
|---|---|---|
| `Cannot find module 'node:sqlite'` / `DatabaseSync is not a constructor` | Node.js старше 22.13 | Обновить Node.js до 24 LTS |
| `npm ci` ругается на lock-файл | Изменён `package.json` или старый npm | Не правьте `package.json`; используйте npm из комплекта Node 24 |
| `Для публикации настройте DATABASE_URL…` | Запуск на Vercel без переменных | Задать все переменные в настройках хостинга |
| `Не настроен доступ владельца` | Production с `DATABASE_URL`, но без `SESSION_SECRET`/`OWNER_PASSWORD` | Задать обе переменные |
| 3D-модели не появляются, видны только постеры | Нет WebGL или блокируется загрузка `/models/*.glb` | Проверить консоль браузера и доступность `public/models` |
| Сборка падает на `sharp` | Не скачался бинарник под платформу | `npm ci` с доступом к интернету; на Linux — glibc/musl-совместимая сборка |
